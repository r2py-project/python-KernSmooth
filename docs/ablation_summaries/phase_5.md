# Research Report: r2py Ablation Protocol — Phase 5 (Root-Cause Investigation of the Placebo-vs-Guides Inversion, Fortran-Binding-Strategy Discovery, and Confound-Adjusted Statistical Re-Analysis)

**Repository**: `python-KernSmooth` (branch `main`)
**Session scope**: Deep, file-level re-investigation of the Phase 4 finding that Condition P (placebo) outperformed Condition G (guides) on aggregate `pytest` failure counts; discovery, via direct inspection of the 30 per-replicate JSON conversion artifacts and the raw JUnit/pytest logs from the Phase 4 test run, that this result is dominated by a single rare, condition-independent, all-or-nothing bug (a botched direct call to the compiled `_KernSmooth` Fortran/f2py binding) rather than by any genuine effect of the placebo instructions; computation of confound-adjusted (exclusion) statistics and formal two-sample significance tests (Mann-Whitney U, Welch's t) for the guides-vs-placebo and placebo-vs-no_guides comparisons, both before and after exclusion; and persistence of all derived artifacts as three new CSV files in `ablation/conversion_guides/results/`.

---

### 1. Abstract

This session began with a user request to read all four prior `docs/ablation_summaries/phase_{1,2,3,4}.md` reports and investigate why Condition P (placebo) showed a lower mean `pytest` failure rate than Condition G (guides) in the Phase 4 build-and-test results (46.3 vs. 56.8 failed tests out of 518, averaged over 10 replicates each). Rather than accepting the aggregate condition-level means at face value, the investigation traced the gap to its source at the level of individual converted functions, individual replicate JSON artifacts, and individual JUnit test-failure messages, uncovering that a single binary, run-wide translation-strategy choice — whether a replicate's agent calls the compiled Fortran extension (`_KernSmooth.locpol`, `_KernSmooth.cp`, etc.) directly or reimplements the underlying numerical routine in pure NumPy — determines, almost deterministically, whether that replicate suffers a catastrophic (100+ failed tests) or a normal (~20–70 failed tests) outcome. This confound was found to be distributed unevenly across the three conditions by chance in the n=10-per-condition sample (3/10 guides replicates, 3/10 no_guides replicates, but only 1/10 placebo replicates chose the failure-prone binding strategy), and to be sufficient by itself to reverse the original guides-vs-placebo ranking once controlled for. The session concludes with confound-adjusted summary statistics, formal significance tests (none of which reach conventional significance at this sample size, in either the original or the adjusted data), and three new CSV artifacts written to `ablation/conversion_guides/results/`.

#### 2.3 Discovery of the bimodal, all-or-nothing failure pattern

- Computed per-replicate, per-function failure counts for `locpoly` directly from `raw_test_results.csv` (grouping by `condition`, `replicate`, filtering `function == "locpoly"`), revealing an exactly bimodal distribution: every replicate scored either 0/74 or 58/74 (or, in one `no_guides` case, 74/74) failed `locpoly` tests — no intermediate values. Counts: guides replicates 5, 8, 9 at 58/74 (all others 0/74); no_guides replicates 1 (74/74), 4 and 7 (58/74, all others 0/74, except replicate 8 at 30/74); placebo replicate 7 at 58/74 (all others 0/74).
- Repeated the identical per-replicate breakdown for `dpill` (83 tests/replicate), finding a correlated but not identical pattern: a persistent "floor" of 9–10 failed tests present in nearly every replicate regardless of condition (attributed to genuine numerical-accuracy divergence from the R oracle, see §2.5), punctuated by the same subset of replicates (guides 5/8/9; no_guides 1/4/6/7/8; placebo 2/4/7) spiking to 52–83 failed tests.
- Extracted representative failure messages via JUnit `<failure message>` text: `guides_5.xml`'s `locpoly` failures (`test_locpoly_truncate_true`, `test_locpoly_truncate_false`, `test_locpoly_regression_two_observations`, and 55 others) all read `_KernSmooth.error: (shape(ss, 0) == m) failed for 1st keyword m: locpol:m=0`; `guides_5.xml`'s `dpill` failures (`test_dpill_n10_matches_r`, `test_dpill_n20_matches_r`, `test_dpill_scale_invariance_large_c`, and 58 others) read `_KernSmooth.error: (shape(x, 0) == n) failed for 1st keyword n: cp:n=0` — an f2py-generated shape-inference error, structurally identical in both cases but naming a different compiled routine (`locpol` vs. `cp`), confirming this is a *class* of error (malformed f2py call for a compiled `_KernSmooth` routine), not a single isolated typo.

#### 2.4 Isolating the causal variable: direct-binding vs. NumPy-reimplementation strategy

- Programmatically inspected every `locpoly.json`'s `function_body` array across all 30 replicates (`ablation/conversion_guides/{guides,no_guides,placebo}/{1..10}/all.R/locpoly.json`) for a non-comment occurrence of the literal substring `_KernSmooth.locpol(`, correcting an initial false-positive (guides replicate 3 contained the string only inside a commented-out fallback code block documenting a *hypothetical* future binding, not an executed call) by filtering out lines whose stripped form begins with `#`.
- Classified all 30 `locpoly.json` files as `CALLS_FORTRAN` (direct binding call present in executable code) or `REIMPLEMENTS` (pure-NumPy reimplementation of the Fortran algorithm): guides {5, 8, 9} = `CALLS_FORTRAN`; no_guides {1, 4, 7} = `CALLS_FORTRAN`; placebo {7} = `CALLS_FORTRAN`; all remaining 23 replicates = `REIMPLEMENTS`.
- Extended the identical classification to `cpblock.json` (the source of the `cp:n=0` error implicated in `dpill`'s failures) and found an **exactly identical** replicate set: guides {5, 8, 9}, no_guides {1, 4, 7}, placebo {7} — establishing that the choice is not made independently per function.
- Further extended the check to `sdiag.json`, `sstdiag.json`, `blkest.json`, `rlbin.json`, and `linbin.json` for the same seven flagged replicates: `sdiag`, `blkest`, `rlbin`, and `linbin` all showed `CALLS_FORTRAN` in exactly the same seven replicates and `REIMPLEMENTS` in all others; `sstdiag` showed `REIMPLEMENTS` in all 30 replicates without exception (i.e., no replicate, regardless of its general strategy, ever attempted a direct `_KernSmooth.sstdiag` binding call). This confirmed the central finding: **the choice to call compiled Fortran bindings directly, versus reimplementing in NumPy, is a single categorical decision made once per replicate and then applied uniformly across (almost) every Fortran-backed function in that replicate's conversion run** — not 46 or 16 independent per-construct or per-function coin flips.
- Checked whether this strategy choice caused collateral damage to functions depending only on the (also directly-bound, in these replicates) `linbin` routine — `bkde`, `bkde2D`, `bkfe`, `dpih`, `dpik` — by computing their per-replicate failure counts for guides replicates 5, 8, 9 specifically. Found only 0–2 failures per function in each case (e.g., guides replicate 5: `bkde` 1/57, `bkde2D` 0/63, `bkfe` 2/51, `dpih` 1/71, `dpik` 2/119) — near-baseline, in contrast to `locpoly`'s 58/74 and `dpill`'s 61/83 in the same replicates. This established that the direct-binding strategy is catastrophically failure-prone specifically for the `locpol` and `cp` f2py signatures (both taking numerous array/scalar arguments with implicit, f2py-inferred shape parameters), while the simpler `linbin` binding signature is evidently handled correctly by the same agents in the same replicates, localizing the damage to `locpoly` and (via internal-dependency cascade) `dpill` rather than contaminating the whole package.
- Traced the instructional source of the "map external calls directly to `_KernSmooth`" directive to `.claude/agents/convert-r-function-to-python.md` §Step 2 ("External Dependencies: Map external calls directly to Python's `_KernSmooth` module... Map `.Fortran(F_sdiag)` directly to `_KernSmooth.sdiag()`..."), a fixed instruction present identically in the agent definition regardless of which of the three ablation guide corpora (`language_dependency_analysis/conversion_guides/`, the placebo corpus, or nothing) is supplied at invocation time. Confirmed, by reading `seq.md`, `round.md`, and `matrix.md` from `language_dependency_analysis/conversion_guides/` in full, that none of the 46 real per-construct guides (nor the single placebo document) contain any content addressing f2py/Fortran binding call conventions — the guides corpus is scoped entirely to R base-function-to-NumPy translation (e.g., `seq()` → `numpy.linspace()`, `round()` → `numpy.round()`, `matrix()` → `numpy.zeros`/`numpy.reshape`), and their content was independently judged accurate and non-misleading on direct reading. This ruled out "the real guides actively mislead the agent toward the risky binding strategy" as a mechanistic explanation, leaving sampling variance in an apparently guide-content-independent binary choice as the best-supported account.

#### 2.5 Quantitative confound-adjustment and statistical testing

- Computed, from `ablation/conversion_guides/results/per_replicate_totals.csv`, the sum of `total_failed` across the three "direct-binding" replicates per condition versus the condition total: guides {5, 8, 9} = 125 + 125 + 126 = 376 of 568 total failures (66.2%); no_guides {1, 4, 7} = 518 + 126 + 230 = 874 of 1,312 (66.6%); placebo {7} = 135 of 463 (29.2%).
- Derived confound-adjusted per-condition statistics by excluding these replicates: guides (n=7, replicates 1,2,3,4,6,7,10) mean 27.43 failed/replicate (std 16.07, min 17, max 62, pass rate 94.70%); placebo (n=9, replicates 1–6,8,9,10) mean 36.44 (std 19.10, min 19, max 69, pass rate 92.96%); no_guides (n=7, replicates 2,3,5,6,8,9,10) mean 62.57 (std 58.97, min 18, max 174, pass rate 87.92%) — noting this **reverses** the original guides-vs-placebo ranking (guides now lower failure count than placebo) while leaving no_guides clearly the worst condition under either accounting.
- Ran formal two-sample significance tests via `scipy.stats`, given that replicate indices are not paired across conditions (replicate `i` in guides bears no relationship to replicate `i` in placebo — each is an independent agent invocation): Mann-Whitney U (rank-based, primary, chosen for robustness to the demonstrated non-normal/bimodal shape of the per-replicate failure-count distributions) and Welch's unequal-variance t-test (secondary/reference), for guides-vs-placebo, placebo-vs-no_guides, and (for completeness) guides-vs-no_guides, in both the original (n=10 vs. n=10) and confound-adjusted (n=7 vs. n=9, etc.) datasets.
- Results (all two-sided): original guides-vs-placebo, U=43.0, p=0.619 (Mann-Whitney), t=0.546, p=0.593 (Welch); original placebo-vs-no_guides, U=34.0, p=0.239, t=−1.698, p=0.120; adjusted guides-vs-placebo, U=16.0, p=0.104, t=−1.025, p=0.323; adjusted placebo-vs-no_guides, U=27.0, p=0.669, t=−1.127, p=0.297. None of these six comparisons (nor the two supplementary guides-vs-no_guides comparisons, p=0.173 and p=0.159/0.173) reaches the conventional α=0.05 significance threshold in either direction, in either dataset.
- Presented both the original and confound-adjusted summary tables, together with the explicit per-condition included/excluded replicate lists and the full six-comparison significance-test table, directly to the user in chat form (not as a separate file at that point in the session).

### 3. Key Findings & Results

- **The Phase 4 "placebo beats guides" result is real but was never statistically significant** (original guides-vs-placebo Mann-Whitney p=0.619) and should not have been read as evidence of an effect even before any confound adjustment — a point Phase 4 itself gestured toward (§3, "not distinguishable from noise") but did not follow through with a formal test.
- **A single categorical, run-wide translation-strategy decision — direct compiled-Fortran-binding call vs. pure-NumPy reimplementation — is responsible for the large majority of both the aggregate condition-level gap and the extreme within-condition variance** (Phase 4's own flagged std ≈ mean pattern). This decision is made once per replicate and applied consistently across at least six Fortran-backed routines (`locpol`, `cp`, `blkest`, `rlbin`, `sdiag`, `linbin`), confirmed by exhaustive per-file inspection.
- **The direct-binding strategy is highly failure-prone specifically for the `locpol` and `cp` f2py signatures**: all 7 replicates across all 3 conditions that attempted it produced an identical class of error (`_KernSmooth.error: (shape(<arr>, 0) == <n>) failed for 1st keyword <n>: <routine>:<n>=0`), while the same replicates' direct calls to the simpler `linbin` signature succeeded (near-baseline failure counts in `bkde`/`bkde2D`/`bkfe`/`dpih`/`dpik`). No replicate, in any condition, ever attempted a direct `sstdiag` binding call.
- **The instruction driving this strategy choice is condition-invariant**: it originates from the fixed agent definition `.claude/agents/convert-r-function-to-python.md`, not from the ablation-varied guide corpora. Direct reading of `language_dependency_analysis/conversion_guides/{seq,round,matrix}.md` found their content accurate and not misleading, and none of the 46 real guides (nor the placebo text) address f2py/Fortran calling conventions at all — ruling out a direct causal story for why guides content specifically would provoke this failure mode more often.
- **The 3-vs-3-vs-1 distribution of this binary event across guides/no_guides/placebo (10 replicates each) is consistent with sampling noise**: Fisher's-exact-style reasoning and the Mann-Whitney/Welch tests on the resulting failure counts both fail to reach significance at n=7–10 per group.
- **Confound-adjusted statistics reverse the original ranking**: excluding the direct-binding replicates, guides' mean failure rate (27.43/518, 94.70% pass) is numerically *lower* than placebo's (36.44/518, 92.96% pass) — consistent with, and reinforcing, the function-level pattern already visible in `bkde`, `dpih`, and `dpik`, where guides outperformed placebo cleanly even in the unadjusted data. This adjusted comparison is itself not statistically significant (p=0.104, Mann-Whitney), so it is reported as a suggestive reversal of the point estimate, not as a validated effect.
- **no_guides remains the clearly worst-performing condition under both accountings** (74.67% pass rate original; 87.92% even after excluding its own 3 direct-binding-attempt replicates), consistent with H1 of the pre-registered protocol (guides materially reduce translation error relative to no guides) — though this comparison is likewise not statistically significant at the current sample size (placebo-vs-no_guides p=0.239 original, p=0.669 adjusted; guides-vs-no_guides p=0.173/0.159).
- **Three new reproducible CSV artifacts** written to `ablation/conversion_guides/results/`: `fortran_binding_strategy.csv`, `exclusion_analysis_summary.csv`, `significance_tests.csv`, all independently re-derived from source JSON/CSV rather than transcribed, and cross-verified to match the chat-reported figures exactly.
- **Raw JUnit/pytest artifacts from Phase 4, though never committed to the repository, were recovered intact** from a prior session's scratchpad directory (`/tmp/claude-241661/.../5b895aff-.../scratchpad/junit/`), enabling this session's failure-message-level analysis; this location is not guaranteed to persist and is not part of the repository's own provenance chain.

### 4. Conclusion & Next Steps

The session's objective — investigating why Condition P (placebo) outperformed Condition G (guides) in Phase 4's aggregate results — is complete: the effect was traced to a single, rare, condition-independent, run-wide implementation-strategy decision (attempting a direct f2py binding call to `_KernSmooth.locpol`/`cp`, which fails in 100% of the 7 observed attempts across all conditions) that happened, by chance in a 10-replicates-per-condition sample, to be drawn 3× as often in guides as in placebo. Formal significance testing shows neither the original nor the confound-adjusted guides-vs-placebo or placebo-vs-no_guides gaps are statistically distinguishable from noise at this sample size, and the confound-adjusted point estimates in fact favor guides over placebo, reversing the unadjusted headline number. This finding was persisted as a project memory (`project_ablation_placebo_vs_guides.md` in the user's memory store) for continuity into future sessions, particularly paper-writing work referencing the ablation results, and as three new CSV files in `ablation/conversion_guides/results/`. Immediate next steps, none undertaken in this session: (1) execute the protocol's originally pre-registered mixed-effects logistic regression / paired-Wilcoxon analysis plan (still outstanding since Phase 1) rather than relying on unpaired condition-level comparisons; (2) either fix the systemic f2py-binding-call failure mode (so that "attempt direct binding" ceases to be an effectively coin-flip catastrophic-failure trigger) or explicitly model/stratify by this binary covariate in any formal write-up, since it currently dominates the between-condition variance; (3) increase replicate count beyond n=10/condition if a definitive guides-vs-placebo effect size is required for publication, given that none of the current pairwise comparisons approach significance; (4) decide whether to commit the three new Phase 5 CSV artifacts (`fortran_binding_strategy.csv`, `exclusion_analysis_summary.csv`, `significance_tests.csv`) alongside the still-uncommitted Phase 4 artifacts (30 modified `pyproject.toml` files, `ablation/conversion_guides/results/`), none of which have been committed to git as of this session's end; (5) apply this same direct-binding-strategy audit to the `no_guides` condition's own internal variance and to any future confirmatory-tier run on `rpart`, where an analogous compiled-extension binding pattern may recur.
